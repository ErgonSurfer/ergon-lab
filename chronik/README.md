# Chronik build-only boundary

This directory starts the reviewed Chronik implementation without changing the
node runtime. `BUILD_CHRONIK_BUILD_ONLY` defaults to `OFF`. In that state CMake
does not enter this directory, discover Rust, invoke Cargo, add a node compile
definition, or change an executable link graph.

When explicitly enabled, the `chronik_build_only` target compiles only these
dormant Rust packages:

- `abc-rust-error`
- `abc-rust-lint`
- `bitcoinsuite-core`
- `bitcoinsuite-slp` (SLP and ALP parsing and verification primitives)

It does not import or build the Chronik C++ bridge, indexer, database, HTTP or
WebSocket server, protobuf API, plugins, callbacks, threads, sockets, or data
paths. It is not linked to `bitcoind`, `bitcoin-cli`, `bitcoin-tx`, or any
production library. The node remains correct and standalone with Chronik
compiled out.

## Native-assets boundary

- Recognized or observed in transactions and blocks: none. This build-only
  boundary compiles and tests dormant SLP and ALP parsing and verification
  primitives, but no node callback or block input reaches them.
- Indexed or reconstructed data: none.
- Authoritative token validation or token state: none.
- Governed consensus activation: none.

## Build and test

Dependency versions are fixed by the committed lockfile. A new machine must
populate its Cargo cache once from the locked public dependency set. Set
`CHRONIK_CARGO_HOME` at configure time to keep that cache outside the source
tree and use the same path for the fetch:

```sh
CARGO_HOME=/absolute/path/cargo-home \
  cargo fetch --locked --manifest-path chronik/Cargo.toml
```

The governed build itself is offline:

```sh
cmake -S . -B /absolute/path/build-on -GNinja \
  -DBUILD_CHRONIK_BUILD_ONLY=ON \
  -DCHRONIK_CARGO_HOME=/absolute/path/cargo-home
cmake --build /absolute/path/build-on --target chronik_build_only
cmake --build /absolute/path/build-on --target check-chronik-build-only
```

Build directories and Cargo outputs belong outside the source tree. Enabling
this boundary is not evidence of runtime indexing, API compatibility, or
consensus behavior. Its exit gate is an isolated Rust build/test plus identical
node executable bytes and unchanged link dependencies between fresh `OFF` and
`ON` builds.
